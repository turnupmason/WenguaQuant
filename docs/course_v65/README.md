# V6.5：把对象、属性、方向与所问结论连起来

V6.4的实答表明：模型能复现部分起局字段和星位，但星与宫比较混淆、整段纠错仍错，否定条件会丢失，具体格名会被一般五行关系替代。两组更低的验证loss都没有证明整体升级。因此本轮先更换这些课程的教学组织，再用同课程比较已有权重与官方起点；不再追加学习率组合。

## 启动与结果

在 **PowerShell** 粘贴：

```powershell
Set-Location "$env:USERPROFILE\WenguaQuant"
git pull --ff-only origin main
.\train_wengua_v65.cmd
```

无需下载新教材ZIP或输入口令。启动时从本机已恢复的V6.4来源包生成独立V6.5课程、审阅Excel和SQLite，逐项校验来源SHA；使用原来兄弟目录WenguaApp的`local\qwen_env`及已缓存Qwen3-8B。不会改原书、App起盘程序、旧版本课程或任何旧权重。

结果在`local\course_v65\run1\results.html`。正常完成后自动在Downloads生成`Wengua_V65_review_日期_时间.zip`。单独导出：

```powershell
.\export_wengua_v65.cmd
```

中断后重复同一启动命令，自动选本组最后完整封存checkpoint，恢复权重、优化器、学习率与随机状态。新阶段只继承已学权重，另建优化器；同阶段两轮连续使用同一个优化器。完成状态为`complete_review_required`；再次运行会明确显示此前已完成并只导出结果。

## 已完成的验证及边界

真实Qwen tokenizer已处理全部1832视图：最长1135tokens，58708个监督tokens，训练/生成回答前缀与标签遮罩逐条相同，完整答案未裁切，58个复检输入完整适配。Excel与SQLite全量读回相等。4096是配置上限；本次最长训练样本1135，不能据此声称已做真实4096 GPU压力测试。

真实微型Qwen/PEFT CPU训练已跑通两种起点、各两轮、全部轮末生成；从独立进程检查点恢复后的最终参数与不中断训练逐张量相等。新增训练开始检查会在用户实际CUDA模型上比较缓存生成与完整前缀forward的前两步logits，记录LoRA非零状态和数值影响；检查本身不更新权重并保存随机状态。独立原生CE/有界CE的loss、全部梯度与token归一化一致。

这些检查验证软件与数据合同，不证明本机8B专业回答已改善。真实语义进步要在本轮完整回答中对照父模型、官方模型与每轮结果，尤其检查理由尾句、否定条件和跨对象切换。全部旧权重保留。
