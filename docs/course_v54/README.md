## 循环与恢复

同一V5.3 step256分别建立两条独立路线：学习率`1e-5`、`2e-5`，各2轮。结构保持r16、alpha32、dropout .05、q/k/v/o、4096上下文，预热.05。先做同结构16步压力测试，smoke权重不用作正式父模型；两组可复用相同配置/数据/设备/内核的显存证明。

新阶段保留旧权重，建立新优化器与cosine计划；同组epoch之间优化器连续。每25更新和完整epoch保存完整checkpoint。重新执行相同命令会读取经过合同/SHA检查的最后完整checkpoint，恢复优化器、调度器和随机状态。进程中断后没保存的少量步骤可能需要重跑，不能承诺每个微批次均已落盘。

默认48小时执行预算；到预算附近保存后暂停，重新执行继续。不会因为罕见格名闭卷分数低，在64/128/256步再强行中止课程；严重运行错误仍明确停止。两条路线完成后状态是`complete_review_required`，表示计划已完成、等待审阅，**不是崩溃，也不是获准上线**。不保证选中某条新模型，未达新门槛保留旧父模型。

需要显式checkpoint时，路径必须属于当前V5.4输出和同一组完整训练合同：

```powershell
# 示例：将路径替换成实际存在的完整 checkpoint-XXX 目录
.\train_wengua_v54.cmd --resume-from-checkpoint "C:\Users\wtmas\WenguaQuant\local\course_v54\run1\trials\source_lr_1em05\cycle_01\trainer\checkpoint-XXX"
```

不要为了更换教材，把V5.4的`resume_from_checkpoint`指向旧V5.3优化器。跨教材继承权重与同一教材恢复checkpoint是两件不同的事。

## 每轮怎么看

本轮固定128开发题：方向25、门宫12、身份10、属性8、来源事实16、天地盘14、条件6、原盘方向18、案例19。事实、显式错误推导和引用分别计分；开放条件/案例仍需原文审阅。S编号只适用于带编号的实际RAG，不对无编号原书案例强行扣“缺引用”。引用成员通过不等于语义支持已证明。

父权重先答同一128题；每轮都保存新128题结果、**原封不动的V5.3旧128题**、**原18道实际RAG输入**。后两者属于已见回归，旧错位对话不再当作新教师或专家金标准。旧基础分数未修改；新来源应用目标也不能宣称为未见现实预测能力。

新自动事实门槛：五行方向≥.90、门宫≥.80、身份≥.85、来源事实≥.80、天地盘≥.80、属性≥.90、原盘方向≥.80，实际引用≥.90；各组相对同一父基线下降不得超过.05。通过仅推荐人工审阅；19领域的完整案例语义仍不能自动批准。闭卷罕见名词另列，不以它阻止有证据的课程学习。

## 训练后的实际RAG

若新候选达到自动门槛，可用同一知识检索入口试问并保存实际原答/来源检查：

```powershell
& ..\WenguaApp\local\qwen_env\Scripts\python.exe -X utf8 -m wengua_course_v54 ask --question "女儿代问父亲看病，不知道父亲出生年，患者和疾病分别看什么？" --domain health
```
