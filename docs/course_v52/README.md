# V5.2：两书课程修订与可恢复训练

**暂停新增古籍。本阶段只用《神奇之门》《开悟之门》，先完成课程修订、既有权重对照和本机续训。** 已整理的第三书原资料保留，未进入本轮。旧人工算分、非书教师、模型错答均不作训练目标。

## 这次实际改了什么

- 新版4,131条核心课程：train 3,721，development 400，已见diagnostic 10。旧题不是靠同义改写扩成更多条；10,980条旧非test任务逐项记录保留、替换或来源索引处置，933条原test只保留封存指纹，不用于本轮修课/选择。
- 所有7,614项课程材料、194案、1,008条作者原分析保留；新SQLite逐条写入再读回相等。标题仍是索引结构，不再作为内容问答。两书完整原文/RAG快照继续保留，本次不重写旧库。
- 202组来源审阅的条件/定义/纠错设计，带257个字面支持片段。包括本人/父母代问考试，女儿问父病/父亲本人问病，缺出生年，河图与宫数，戊戊同干交换/丁壬异干交换，门克宫/宫克门，多领域同符号取用，原断/回访/反馈日期。
- 作者分析不再把整段同时放在输入和答案。能安全识别的原文因果连接转为“已核对证据→对应结论及简短依据”；其他原分析保留在来源/分析索引中，不编造拆分，不要求模型机械抄写。
- 特别修正A/B比较题：原书对弟弟瘫痪与父亲患病作比较，保留两个不同病例及A/B标签；不能把最后对B的判断归给A。康复/考试相邻事件只使用各自窄段，不再整块塞入同一问题。
- 旧来源中有8处较宽的案例关联元数据，已逐项确认在同一保守事件家族；题目只使用明确案例窗口，原关联留档。无未处置跨家族来源别名。

**记录变少不等于删书。** 原书、原案、原分析和旧题处置都能查；减少的是标题抄写、含混第几段任务和重复全文目标。不能安全改成问答的材料保留为来源，不假称已完成独立断案教学。

## 新评估的范围与限度

每个候选使用完全相同的128题，覆盖19个案例领域、28个案例家族：106个明确事实槽位自动检查，22个开放回答保留审阅。领域包括疾病、考试、就业、婚姻、求财、失物、行人、诉讼、刑事、出行、体育、怀孕、地理、天气等。少数单例领域不伪造额外独立事件。

已知旧错例作为补课/已见诊断；新阶段开发家族整体退出本轮train。同家族题不跨训练/开发；本次也核对未出现相同案例问题或相同完整原书抄盘跨两侧。**既有权重可能接触过这些来源，这仍是开发检查，不是全新盲测或现实预测准确率。**

自动检查限定名称、数字对、身份主用神、状态、宫间方向、同干交换等可明确核对的槽位。关键词rubric即使命中也保持`needs_review`，不计作语义正确；整案分析不由字符串匹配自动验收。报告中的约束通过比例是评估指标，不是传统人工吉凶算分，更不是预测概率。

## 自动运行的顺序

1. 校验教材、原程序指纹、封存父适配器回执；不采用smoke权重，不导入父优化器。
2. 用同一开发题比较本机V4父权重、V5.1第一轮和第二轮（存在且完整时）。按有限事实约束挑续训起点，不按文件新旧或NLL直接选。
3. 保持Qwen3-8B、4096上限、r16/alpha32/dropout0.05、q/k/v/o与原训练栈；只比较学习率 **5e-6、1e-5**，每组 **2个连续epoch**，从同一选定父权重分别开始。
4. 每组独立进程先作32次真实课程压力更新；包含实际最长/高监督密度样本，不用填充文本声称完整4k能力。可核对的压力指纹命中时只复用显存证明，绝不把压力权重接成正式模型。
5. 正式数据按条件题增加复习权重：3,721条核心训练课程展开/复习后 **5,109个训练视图**，不是5,109个独立知识。每组约320步/epoch、640正式更新，两组合计1,280正式更新；实际计划以本机准备回执为准。
6. 每轮保留loss、实际回答与约束检查，所有候选权重都保留。生成`review_nominee.json`仅指有限检查下的审阅候选；整案仍待检查，不自动合并或上线。

最长预算默认48小时；两组完成即停止，不会为了凑满时长无限重训。配置或教材改变会拒绝接管旧run，避免把恢复误当新训练。不得在两组之间改教材。

## Windows CMD启动

使用现有WenguaApp的Python环境。两个仓库放在用户目录并列；不要求新建环境、不重新下载8B底座。

```bat
cd /d "%USERPROFILE%"
if not exist "WenguaQuant\.git" git clone https://github.com/turnupmason/WenguaQuant.git
cd /d "%USERPROFILE%\WenguaQuant"
git pull --ff-only origin main
train_wengua_v52.cmd
```

首次自动恢复教材，粘贴此前V4/V5.1的64位教材口令，输入可见；**不是输入ZIP路径**。资料密文在Git中，口令不入Git。恢复成功后自动比较权重、压力测试并开始两组续训。若使用PowerShell，在对应目录运行 ` .\train_wengua_v52.cmd`。

课程检查（不启动模型）：

```bat
"%USERPROFILE%\WenguaApp\local\qwen_env\Scripts\python.exe" -X utf8 -m wengua_course check
```

PyCharm也可使用同一解释器，工作目录选WenguaQuant，模块选`wengua_course`，参数为`run --resume`。

## 中断后继续

再次运行同一CMD入口即可。新课程阶段继承LoRA并新建优化器；**同一组中断**则恢复完整checkpoint的权重、优化器、学习率计划及随机状态。默认寻找当前组最后完整、回执有效的checkpoint；不会无提示从头重训。

需要指定时，只能指定本次V5.2对应学习率组中的完整checkpoint，例如：

```bat
train_wengua_v52.cmd --resume-from-checkpoint "local\course_v52\run1\trials\lr_5em06\cycle_01\trainer\checkpoint-250"
```

示例250不代表本机一定已有该目录。V5.1的checkpoint不能作为新教材阶段的优化器恢复路径；V5.1权重通过已核对的epoch adapter继承。

## 在哪里看、怎样把结果给我

- 全课程/194案/1008分析/全部材料/旧题处置Excel：`local\course_v52_data\Wengua_两书条件课程_V52_全量审阅.xlsx`。
- 新的两书课程数据库：`local\course_v52_data\Wengua_两书课程_V52.sqlite3`。有独立材料、课程、案例、作者步骤及来源/案例关联表，未改旧研究库。
- 训练可视化与逐题原答：`local\course_v52\run1\results.html`；阶段状态：同目录`run_status.json`。
- 现有App起盘和旧V4/V5.1数据、检查点保持原样。

跑完或中断需要检查时，在CMD运行：

```bat
"%USERPROFILE%\WenguaApp\local\qwen_env\Scripts\python.exe" -X utf8 -m wengua_course export
```

生成`Downloads\Wengua_V52_review.zip`，包含状态、各轮实际回答、检查记录和失败日志，排除模型权重、优化器和教材。重复导出时先移动旧ZIP，防止无意覆盖。

- 来源支持片段、933项原测试封存指纹、案例家族/题目/完整抄盘的本阶段隔离、课程索引与SQL外键逐项核对。

- 微型随机CPU Qwen3/PEFT用于父权重继承、初始优化器为空、跨进程完整恢复、两组有限loop和评估/导出接线检查。**这不是实际8B/4080验证。** 当前版本在真实显卡上的显存与回答效果，需要本机日志确认；不会声称专业百分百无错。
