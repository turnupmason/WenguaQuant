金额和日期的判断只针对本次指定来源是否支持，未对现实项目另作调查。相应目标本身有正确规则，不能把错答都归咎于原书或标签错误，更不能改原书迁就模型。

29 道已见诊断还暴露出：

- 把后来得知的实际找物地点、任职结果或办公室情况倒填进作者事前判断。
- 把面试发生日与反馈收到日混写；对“十天”和“五天”没有交代各自起算事件。
- 把“不下雨，最多阴”改成“晴”，改变了作者实际结论。
- 武试规则题第一轮没有提供有效条件；第二轮编造宫位并重复至1024 token上限。
- 疾病康复题的来源块跨入后面的教育事件，第一轮把后一案考试条件混进康复分析。这里既有输入边界问题，也有模型没有锁定所问事件的问题。

这不是“每题都答坏了”：字面星位题、部分作者断语、若干应期来源复述、部分反馈摘要正确。逐题表保留正确、部分正确、漏项、无依据新增和课程缺陷的区别，没有用一个总分抹平它们。

## 4. 为什么现有验证不足以选出专业赢家

235条输出来自：官方底座37条、V4父权重37条、两轮各37条正式验证，加上父权重及两轮各29条已见诊断，共66个不同任务。

**37道正式验证全部属于同一建筑方案案例、同一个事件家族**。其中20道读盘类 = 17道字面读取 + 3道关系；12道案例类主要是原文摘录和作者复述；基础3道、条件2道仍围绕同一故事。检查到该事件家族不在当前 V5.1 train，但这只能证明本阶段家族划分；不能据此保证前阶段从未接触，更不能声称跨领域新盘泛化。

29道诊断中13道来自train、16道来自原validation，而且本身已被反复查看。它们适合定位失败，不是新盲测。最终test没有输出，本次也没有读取最终test题目来设计修补。

正式验证最长输入985 tokens，诊断最长2102，回答预算1024，均可容纳于4096；生成程序遇超长会报错而非静默截断。因此不能把本次这些错答解释为输入被截掉或显存不足。部分案例复述题直接给出了作者目标段，它们验证的是按来源回答，不是模型自行推导该断语。

## 5. 课程制作仍有遗漏，下一版应修什么

这是此前课程整理的遗漏：**仍有24道只回答“九宫盘面：”的标题题，其中train20、validation3、test1**。本次只按答案元数据计数，没有检查最终test题目。标题应保留为结构索引，撤出内容SFT和能力得分；不删除原始资料。冻结 V5.1 包保持不变。

当前train有10,173条核心记录（多轮展开后本轮训练使用10,272个视图）：基础2,783，条件686，读盘3,775，案例2,929。读盘多为短字段；案例中1,974条是补充来源摘录，802条是作者逐步复述。可见资料覆盖不等于复杂技能覆盖，`complete_case` 格式名也不代表每条都在教整盘推理。

具体修订优先级：

1. **先改教学边界与目标。** 标题归结构；第几段提问改成明确事实/条件问题；长原文按完整语义单元拆开，保留上下文与来源坐标。隔离相邻事件，分开原断、后披露、反馈与作者纠正。保留原书，不引入旧人工分数。
2. **针对失败制作条件对照。** 同干互换/异干互换、本人/代问、河图/洛书、谁生谁克、预测日期/反馈日期。每个答案先答所问结果，再给必要条件和具体证据；缺信息才说明缺什么，不机械附加一段泛泛禁令。
3. **提高真正应用任务的覆盖。** 按领域取用、实际力量和作用条件、冲突证据、整案摘要分别设任务；按来源支持程度决定能否生成，不靠同义改写堆数量。全文保存完整，但不是每次都把后续反馈塞进事前预测输入。
4. **先有合适的评估，再调轮数。** 另建覆盖两书多领域、多事件家族的开发检查；把闭卷知识、给来源阅读、给盘应用、多轮身份切换分开。已经看过的37+29题归入开发诊断，不再叫新测试。最终测试继续封存。
5. **模型选择必须看语义。** 单列无依据金额/日期、关系反向、用神身份、来源阶段错置、重复等失败。语言loss可以辅助观察，不作为自动专业晋升依据。错误记录本身不能进入古籍RAG或成为自动SFT答案。

对当前train完全相同输入的不同目标做了检查，没有发现规范化后不同答案的冲突组；这不证明所有课程都没有语义问题。正确目标已经存在而模型仍答错的部分，后续还需检查抽样权重、学习/遗忘平衡和多轮应用表现，不能只增加epoch。
