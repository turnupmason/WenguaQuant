# V6.4 条件、比较对象和纠错续训

V6.3在原题上能复现答案，但人物关系、输入结构和比较对象一变，仍会取错用神；有些正确首句后面还跟着错误解释。本版本保留原书，重组这些教学任务，继承已选的V6.3高率第7轮step-371，做两组各两轮的定向短训，保存每个阶段的完整实答。

## 本次课程

567条训练核心展开成608个完整助手监督回合，另有40条新开发题。核心记录与监督回合是两种计数：一条多轮对话可以有多个需要学习的助手回答。每一回合仍保留其当时完整上下文，没有把以后才给的资料提前放入输入。

| 训练任务 | 核心数与具体变化 |
| --- | --- |
| 人物与字段 | 143条直接取用/字段缺值/多轮课；24次实际关系改变，另有7次关系不变、只补年命的对照。字段值分别覆盖已知、null与未提供。另有14条人物取用核对、4条关系不明需确认。 |
| 生克与纠错 | 25条直接关系；同一对五行分别给正确说法和错误说法，共50条核对题，另10条修正同一答案前后矛盾。 |
| 门宫 | 64种门宫配对和22条真假标注核对，保留必要的属性、方向、名称，移除128次旧固定范围尾句的重复教学。 |
| 比较对象 | 54条当前落宫/星与本宫/两星所在宫课，其中6条在同一组位置上切换比较对象。物理位置只来自App1080库的字面星位；6种旋转用于教学，2种用于本阶段开发。没有使用该库里的评分、81格定性或真假空亡表。 |
| 领域条件 | 婚姻24、放贷12、卖货12、退役9、六合跨领域14；分别核对未知、明确不具备、已具备，以及所问一方和所问目标。 |
| 类型与考试 | 8条星/干同宫状态分别核对；6条本人/家长代问考试。 |
| 阅读证据 | 32条直接来源对应/引用原句，4条限定“当前这段没有该内容”的对照；不能把局部缺证据说成全书没有规则，也不能否认已经给出的原文。 |
| 保留的来源对话 | 60条既有来源对话逐字保留，包括4条作者案例复盘；不是把模型错答改成教师。 |

原405训练核心各有处置记录，原216材料单元和194案例的划分登记保留。本轮教师实际使用41个来源单元；只有4条核心关联原书案例，所以**这不是两书全部案例课程已经完成**。原两书总库、原RAG索引、194案/1008作者分析档案和App起盘程序不受这份阶段课程覆盖。新生成的题是有来源的教学条件，不作为新历史事件或现实结果样本。

当前原test保持封存。新题和旧题均是已知知识上的开发检查，不能称为独立真实案件准确率或预测概率。

## 权重、参数和循环

父权重固定为 `local/course_v63/run1/trials/lr_1em04/cycle_01/adapters/step-371`，来源报告SHA256 `c12e455e0ba7ef3b923c48f23321f0da624b75de3f4eb88c0800aace24a2457d`。启动时校验正式来源与实际文件，保留不可变副本；不接受其他旧adapter或悄悄改用官方零初始化。它仍是研究候选，不是已经通过全部专业验收的模型。

| 参数 | 本次设置 |

| 调度与恢复 | 新阶段新优化器/余弦计划；同组两轮连续，阶段内恢复优化器、调度器、RNG及数据进度 |

每组先做2次更新的实际数据短测，短测权重不进入正式训练。沿用已经核对的有界CE、融合注意力、80%分配器额度、微批缓存清理和独立worker；没有添加CPU训练回退。

先复用父模型已有74条原答，只补生成40条新开发题的父模型回答。以后每个epoch生成同一套114题：40新开发+12原题+24自然诊断+20原来源开发+18原RAG。两组共4个阶段，456条阶段回答；正式新增回答496条，另加压力短测回答。**父模型的74题不会在每一组再次生成。** 每轮的RAG也都会保存，避免又只比较最低loss的早期权重。

两组结束即进入`complete_review_required`，没有自动追加长训，没有凭关键词或最低loss自动替换模型。原父权重和所有阶段都保留，后续按完整回答核对退步和新增能力。

## 数据核对与审阅

`check`和首次启动会从已有V6.3资料确定性生成课程，不需要新ZIP或口令。全局冻结完整标准JSON，避免gzip或Excel文件的跨平台字节差异影响课程合同。每条新教师绑定原TRAIN来源、原句和条件契约；先核对主客体、人物关系、限定范围，再核对答案。人物主用神、同一对关系的真假说法和证据存在/缺失均有对照。

本地已完成全量分词，608回合最长实际1135tokens，114检查题及完整证据/目标均能放入预算；配置上限4096不意味着已经验证4096长度的训练样本。完整助手回合不裁切，来源不静默丢弃。SQLite逐条读回、Excel完整单元格读回及独立Excel读取均通过。

微型CPU实训验证了非零父权重原样载入、空的新优化器、GAS2含不足一组的末尾微批，以及中断后最终张量与不中断一致；两率循环、缓存原答、中断尾部修复、所有epoch作答、导出和重复启动均有检查。跨平台入口以对应提交GitHub Actions为准。这里没有运行真实8B CUDA训练，实际语义改善仍需这次本机结果确认，不承诺零退步。

## PowerShell启动

```powershell
Set-Location "$env:USERPROFILE\WenguaQuant"
git pull --ff-only origin main
.\train_wengua_v64.cmd
```

这条命令会自动处理课程、父模型补充检查、两组短训和导出。开始补充父答时，从第75条继续是正常的，前74条已经复用。默认24小时预算；中断后重复同一命令恢复最近完整断点。

课程审阅文件在本机：

- `local\course_v64_data\Wengua_V64_条件修复课程.xlsx`：完整对话、参考答、原句和条件出处。
- `local\course_v64_data\course.sqlite3`：阶段课程、来源、405条旧课处置和材料覆盖；不覆盖原总库。
- `local\course_v64\run1\results.html`：训练状态及逐阶段完整回答。

如果只想先生成并看课程，执行：

```powershell
.\..\WenguaApp\local\qwen_env\Scripts\python.exe -X utf8 -m wengua_course_v64 check
```

正常结束后，结果ZIP自动放入“下载”，文件名为`Wengua_V64_review_时间.zip`。也可随时单独导出已有进度：

```powershell
.\export_wengua_v64.cmd
```

不必手工找口令、删除旧模型或改checkpoint路径。显式指定恢复参数时，只能使用本次V6.4对应组的最新完整封存checkpoint，不能指向旧V6.3优化器目录。
