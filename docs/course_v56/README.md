## 训练顺序

| 阶段 | 起点 | 教材/更新数 | 决定方式 |
|---|---|---|---|
| 短训A | 已审核V5.4高学习率step134 | 1600次核心采样、1608个assistant视图；4轮，每组404更新 | 每轮新96题、原V5.5的192题及原18题实际RAG回归 |
| 短训B | V5.5高学习率第1轮step397 | 同一短训课程与计划 | 与A采用相同验收条件，保留全部检查点 |

完整阶段学习率为1e-5和2e-5，各组从同一个通过短训的权重开始。新阶段继承权重、建立新优化器和学习率计划；同阶段跨epoch及checkpoint恢复保持优化器、scheduler和RNG连续。正式训练不采用压力测试权重。

短训验收检查关系方向、定位、门宫、格名、身份、条件、引用及旧题回退，包含出生年边界和六合跨领域对应。没有合格候选时状态为 `needs_course_review`，完整课程不启动；不会以更低loss替代这些条件。开放案例语义仍需逐题审阅，不自动批准专业模型或生产部署。

新192题覆盖19个原案例领域及12个主要领域规则组。旧题是已经暴露的回归题，新的条件问法也不是新观察事件；不称现实预测命中率或全新盲测。

## 显存、保存与恢复

保留已经在用户8B运行中使用的NF4、4096上下文、r16/alpha32、dropout0.05及q/k/v/o LoRA结构，使用已冻结的有界词表loss和fused attention路径。此云端未执行真实8B CUDA训练；启动后仍先做本机真实数据压力测试。

每25次更新及完整epoch保存，最近4份完整optimizer checkpoint受保留策略管理，完整epoch adapter分别保留。中断后重复同一命令，从最近完整checkpoint恢复。需要显式指定时可加：

```powershell
.\train_wengua_v56.cmd --resume-from-checkpoint "local\course_v56\run1\trials\具体参数组\cycle_01\trainer\checkpoint-XXX"
```

默认时间预算72小时，接近预算时保存并暂停；可用 `--hours 24` 设置本次预算。`404`、`650`是优化器更新步数，不是epoch。

训练条结束后还会生成答案、执行回归。控制台会显示 `v56_answer_progress` 的题号和总数；最终状态、逐轮指标、原题、原答和来源目标见 `local\course_v56\run1\results.html`。
