# V6.0：明确课程目标、多领域复盘与同父权重参数比较

这一版继续使用 **V5.8 第一轮 step97 保留基线**。V5.9 两轮都未通过逐题留存，因此不把它们当成已合格父权重。旧模型、旧成绩、原始两书和 App 起盘代码全部保留。V6.0 是新的数据及运行合同，不覆盖 V5.9 输出。

## 先修课程，再比较参数

- 两书的 **7970 材料、194 案例、1008 条作者分析、2049 规则、46 组流程**逐项保留，并存入来源对照数据库。每条作者分析都有教学或归档处置，不以几千种换问法冒充新增证据。
- 登记课程 **8951**；实际训练核心 **5947**，展开多轮后 **5981 个监督视图/轮**。登记量包括来源归档和评估，不能称全部都在训练。
- 346 条遮去原文结论的局部补句题全部退出应用训练。历史事件名称、具体金额或日期若不能由可见条件唯一推出，就保留完整作者复盘，不要求模型猜原句。
- 新建 **852 条有完整原段的作者复盘视图**，其中 687 条属于 train。原有案例视图修正生成的阶段标题，原文未明示的片段不再统一称为“初断”；149 个案例复盘视图参与 train。它们是有作者分析的来源学习，不能冒称模型独立断中了历史案例。
- 增加 **20 组同来源、同专题、不同明确条件及结论的多轮对照**，覆盖求财、就业、诉讼和失物；旧有条件及人物切换课程也保留。120 个带明确合同的助手回合逐回合核对。其他领域仍用其已有规则、流程及来源案例，不补造没有出处的条件题。
- 全体课程逐条检查原文片段归属和完整 4096 token 预算；没有截断条件来塞入上下文。真实教材实际准备为短训 786、完整 5981 监督视图，最长 3189 tokens；SQLite 所有对象读回校验，Excel 的完整问题、回答逐条读回。
- 训练依据仅来自两书。旧人工吉凶分数、其他古籍、模型错误回答不作教师；审阅结果也不进入古籍 RAG。原 test 家族继续封存。

数据库登记有 22 个案例领域；其中时事一项没有可用作者分析，仍按来源归档。生产安全目前没有同家族外的验证案例，不伪造独立验收题。领域覆盖表分别列案例、分析步、训练、验证、封存，**训练有覆盖不等于每个领域已经验证合格**。

Excel 除课程页外，另列 **全部194案例总览、案例完整来源JSON分段、1008条作者原文、1008分析教学处置、领域覆盖**。全部案例 JSON 和作者原文已按序拼接读回，逐字相等；即使没有合适训练题，来源仍能找到。SQLite 的 `cases` 与 `author_analysis` 可直接查询案例分类和逐步原文，完整来源对象另有 SHA 校验的压缩存储。

## 有限 loop

1. 用同一组 **24 题**比较官方 Qwen3-8B 与保留 adapter，保存两边原答、权重身份和输入预算。它是基础能力诊断，不重训整套基座，也不是新的盲测。
2. 三组均从同一份保留权重出发，使用同一份 **768 核心 / 786 监督视图**；每组 **1 epoch、50 次优化器更新**。只比较学习率 `1e-6 / 3e-6 / 1e-5`，种子、数据顺序、LoRA 结构及其他设置相同。
3. 每组比较 **112 题**与 **36 个实际 RAG 包**。112 题为原 80 个稳定输入及 32 个目标明确的规则/条件题。检查器修正了属性错误绑定、人物分支与正常同义表达；父模型和候选使用同一版检查，旧版本成绩不改。
4. 已有正确事实、完整条件和引用逐题保护；其他题的进步不能抵扣退步，而且必须出现新增完整正确项。三组全部跑完比较，失败权重只作研究记录。
5. 有候选通过，才继续完整课程 **1 epoch、374 次更新**。继续训练还要同时保护原基线和已通过短训的候选；完整阶段退步时保留通过短训的权重。三个短训都不过，则保留原基线。
6. 最后只生成一次 **192 题多领域来源审阅**。小套与 RAG 使用 512 token 生成预算，最终来源案例使用 768，分别检查完整输入和参考答案都能容纳。开放作者语义与有限自动事实分开；完成所有步不表示通过专业验收。`retained_best.json` 明确记录实际保留权重及原因。

这保护的是这套固定题中已核对的能力，不能证明所有未见题永不退步。验证 loss 只作学习诊断，不用于替代逐题留存决定；本版不会自动发布为临床、现实概率或专业预测模型。

## 4080 运行与恢复

Qwen3-8B 固定 revision `b968826d9c46dd6066d109eabc6255188de91218`，NF4 QLoRA，4096 上下文；沿用父权重的 `r16 / alpha32 / q,k,v,o`，dropout 0.05、累积 16、cosine、warmup 0.05。更换训练阶段继承 adapter，重新建立优化器；同阶段中断则从完整 checkpoint 恢复模型、优化器、学习率和 RNG。

采用 V5.9 恢复实跑已使用的 **80% 分配器额度**，在完成微批次/更新/验证批次后释放符合条件的闲置缓存，不更改张量精度或跳过样本。每个单元独立进程；心跳不依赖一个最大的文件时间戳，静默会保存诊断，最长宽限有限。原始注意力及有界损失路径继续核对。额度不是对其他应用的显存预留。

## 实际 RAG 问卦

RAG 使用现有两书来源索引，按领域检索规则与作者材料。时间起盘调用 WenguaApp 已有历法及起盘程序；不让模型计算九宫。`--time` 与 `--chart` 二选一，时间按程序要求给明确时区。

```powershell
& "$env:USERPROFILE\WenguaApp\local\qwen_env\Scripts\python.exe" -X utf8 -m wengua_course_v60 ask --question "女儿代问父亲疾病，不知道出生年，应怎样取用神？" --domain health
```

查询只使用 `retained_best.json` 记录并校验的权重。来源、检索输入与原始回答另存；检索到原书案例不算现实预测盲测。本版不将生成的回答重新写成古籍事实。

## 验证边界

源片段和完整 token 核对、SQLite/Excel 读回、加密恢复、软件单测、真实微型 CPU 张量继承及精确恢复、三参数组正/负路径分别验证。CPU 正路径为了检查调度明确注入 fixture 决策，不把随机小模型当成专业合格模型。

真正的 RTX4080 / Qwen3-8B 训练和新问题表现，必须读取本次本机结果。软件通过、引用存在和低 loss 都不能替代这些结果。
